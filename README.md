# Self-Learning SQL Agent

A self-improving agent that fixes broken SQL queries and gets better at it over time. Inspired by the memory and skill-generation concepts in [NousResearch/hermes-agent](https://github.com/nousresearch/hermes-agent).

When a query fails, the agent diagnoses the error, asks Claude to fix it, and writes what it learned into a reusable skill file. On the next run, that skill is injected back into the prompt so Claude has a head start — fewer iterations, better fixes.

---

## How it works

```
broken query
     │
     ▼
execute ──► FAIL
     │
     ├── classify error type
     ├── load matching skill file  (if one exists from a prior run)
     ├── fetch similar past fixes  (from memory.json)
     │
     ▼
Claude prompt: schema + error + skill + past examples
     │
     ▼
Claude returns: fixed query + skill body
     │
     ├── retry query ──► SUCCESS
     ├── write fix to memory.json
     └── write skill to skills/<error_type>.md
```

The more the agent runs, the richer its skill library and memory become — each subsequent run is guided by accumulated knowledge.

## Project structure

```
self-learning-agent/
├── run_demo.py              entry point — runs 5 broken queries
├── config.py                paths, model, MAX_ITERATIONS
│
├── agent/
│   ├── core.py              SQLLearningAgent — main loop
│   ├── memory.py            MemoryStore — reads/writes memory.json
│   ├── skill_manager.py     SkillManager — reads/writes skills/*.md
│   ├── sql_executor.py      SQLExecutor — runs queries against SQLite
│   └── classifier.py        ErrorClassifier — maps error → type
│
├── skills/                  auto-generated skill files (one per error type)
├── data/
│   ├── sample.db            SQLite e-commerce database (auto-created)
│   └── memory.json          failure log + error pattern counts
│
├── architecture.md          ASCII + dataflow diagrams
└── plan.md                  design document
```

## Run

```bash

python run_demo.py
```

Run it a second time to see the agent reuse its learned skills and past fixes.

## Demo queries

The demo feeds five intentionally broken queries against a local SQLite e-commerce database (`categories`, `products`, `customers`, `orders`):

| Query | Error type |
|---|---|
| `SELECT name, price, FROM products` | `syntax_error` |
| `SELECT name, pric FROM products` | `no_such_column` |
| `SELECT * FROM product WHERE price > 10` | `no_such_table` |
| `SELECT customer_name, email FROM customers` | `no_such_column` |
| `SELECT id, name FROM customers JOIN orders ON ...` | `ambiguous_column` |

## What gets persisted

**`data/memory.json`** — written after every fix:
```json
{
  "failures": [
    {
      "id": 0,
      "original_query": "SELECT name, pric FROM products",
      "error_type": "no_such_column",
      "error_message": "no such column: pric",
      "fixed_query": "SELECT name, price FROM products",
      "fix_description": "Corrected typo: 'pric' → 'price'",
      "iterations": 1,
      "success": true,
      "skill_generated": "no_such_column",
      "timestamp": "2026-05-13T00:00:00+00:00"
    }
  ],
  "error_patterns": {
    "no_such_column": { "occurrences": 2, "last_seen": "..." }
  }
}
```

**`skills/<error_type>.md`** — generated by Claude, one file per error type:
```markdown
---
name: no_such_column
description: Fix column name errors in SQL queries
error_types: [no_such_column]
success_rate: 0.95
usage_count: 3
created_at: ...
last_updated: ...
---

## Strategy
...
## Common Patterns
...
## Example
...
```

## Configuration

Edit `config.py` to change defaults:

| Setting | Default | Description |
|---|---|---|
| `ANTHROPIC_MODEL` | `claude-sonnet-4-6` | Model used for all API calls |
| `MAX_ITERATIONS` | `4` | Max fix attempts per query |
| `SKILLS_DIR` | `skills/` | Where skill files are stored |
| `MEMORY_PATH` | `data/memory.json` | Memory file location |
| `SAMPLE_DB_PATH` | `data/sample.db` | SQLite database used by demo |

## Key concepts from Hermes agent

| Hermes concept | This project |
|---|---|
| Memory store | `data/memory.json` — persists every failure and fix across sessions |
| Skill files | `skills/*.md` — Markdown + YAML frontmatter, written by Claude |
| Skill retrieval | `SkillManager.load_skill(error_type)` — fetched by error type at fix time |
| Trajectory recording | `MemoryStore.get_similar_failures()` — past fixes injected into Claude prompt |
| Curator | not implemented (future: merge redundant skills, archive stale ones) |
